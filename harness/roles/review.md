# 役割: 人間レビュー（review）

各ノードの**決定**と、深さ0-2のノードの**分割**を人間が承認または却下する。
提案した AI と前検査した AI は承認できない。

## 1. 決定の承認

### 入力

- 対象ノードの `index.md`
- 祖先チェーン
- `harness/` 一式
- `harness/criteria/precedents.md`

### 確認すること

- 7項目が埋まり、現在有効な決定が一意に読める
- 深さに対応する対象を決めている
  - 深さ0: ペイン・目的・利用者・成功条件・不変条件
  - 深さ1: 課題の範囲と、それに対する解決法
  - 深さ2: 親の決定の詳細化と、それに伴う機能
  - 深さ3: 実装するシステムの境界・振る舞い・受け入れ条件
- 受け入れ条件を人間が理解し、達成を判断できる
- 祖先の目的・制約・seam と矛盾しない
- 仮置きと、実装へ任せる判断が明示されている

承認したら、版参照・承認者・日時・承認種別 `decision` を
`## 承認証跡` に記録し、`status: decision-approved` とする。

## 2. 分割の承認

深さ0-2だけで行う。対象ノードの決定が承認済みで、別実装 AI の前検査を通った提案を読む。

人間は前検査の判定に拘束されない。ただし重大指摘を残したまま承認する場合は、
その理由を承認証跡へ書く。

分割の承認では、次も確認する。

- **子ごとの振り分け**が全ての子について書かれている（責任 / 詳細化の対象 /
  継承する制約 / 割り当てられた受け入れ条件 / `uses_seams` / 親の決定の版参照）
- 子が1つであることを理由に却下しない。深さ0-2は子が1つでも分割する
- 各子が、次の深さの意味に合っている

承認したら、版参照・承認者・日時・承認種別 `split`・対象の分割提案 id を記録し、
`status: split-approved` とする。その後でだけ子ノードを作る。

子を作るときは、**親が振り分けを子の `## 親からの振り分け` へ転記する。**
転記が済んで初めて `children-created`。子はこの節を書き換えない。

提案が前検査後に編集されていたら、承認せず再度 precheck へ戻す。

## 3. 親・祖先を修正した場合

`boundary_request` により親または祖先を修正した場合、そのノードの決定承認は失効する。
内容を修正したノードから順に、必要な最上位の祖先まで決定を承認し直す。

修正によって子の責任、seam、受け入れ条件の割り当てが変わる場合は、分割も前検査と
人間承認をやり直す。上位の決定が確定してから下位ノードを再開する。
