## 親からの振り分け

<!-- 親（change）が split-c1 の承認時に転記した。子は書き換えない。

- 責任: 停止・失効確定・書き直し要求の順序と安全条件を決める
- 詳細化の対象: 本文1の解決法のうち**確定の順序**（`halt` → `ack` → `stale` → `s5`）、
  **再開の判断**（親に残すもの 4b）と、その安全条件。
  **持ち越された重大2件**:
  (1) `c2.impact-set` が失効集合しか運ばず、`却下` / `撤回` がどの先行停止要因と
  影響集合を解除するか未定義。安定した停止理由の相関キーをここで決める。
  (2) **根から持ち越し**: `停止ack → 人間承認 → s2.承認 → 再開ack` の順序が未固定で、
  `s6` の「ack が返るまで確定しない」と読み合わせると循環して読める。
  根が固定したのは「停止・再開が確定より前に完了する」ところまでで、
  ack 集合と順序の状態機械はこのノードの担当
- 継承する制約: 根の不変条件1〜4と `boundary_requests` の例外、根の「親に残すもの」1〜15、
  ツール固有機能に依存しないこと（Codex / Claude の双方で回る）、予算（深さ3・子数5）。
  change の「親に残すもの」1〜11。とくに 4（確定の順序を入れ替えない）、
  4b（再開の条件。`差し替え` は再開の理由にならない）、
  5（ack まで確定しない。タイムアウト・強制確定を置かない）、
  6（`stale` は判定まで。書くのは review ＝人間）、7（`s5` は欠落検査器ではない）、
  10（payload の書式は `authoring` の所有）
- 割り当てられた受け入れ条件: 判定不能時の停止と起票 / 鮮度の可視化（判定まで。書くのは review）/ 停止の先行 /
  再開の適正 / 書き直し要求の搬送
- uses_seams: `c2.impact-set`（`impact` から: 失効集合、または「判定不能」）
- 提供する seam: `c1.authorized-input`（`impact` へ）。および親を経由して外へ出る
  `s5.invalidation` / `s6.halt`（停止と再開）の payload
- 親から降りる入力: `s2.change-event`（`起票` / `差し替え` / `却下` / `撤回` / `承認` のライフサイクル通知）、
  `s4.boundary`、および `halt_ack`。**`uses_seams` には書かない。**
  親（change）が受けて権威化し、この節を更新して降ろす
