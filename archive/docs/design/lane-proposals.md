# レーン分割提案

## 目的

レーンAIが対話中に分割可能性を発見できる利点を残しながら、レーン構成の決定権を人間に保つ。AIによる自動作成の連鎖、脱線、レーン増殖を防ぎ、人間が分割理由を理解してから並列化する。

## 基本原則

1. AIは分割を提案できるが、レーンを作成できない。
2. 人間が`create`を選んだ場合だけAIDEが子レーンを作成する。
3. 提案は理由、目的、対象範囲、依存関係を必須の判断材料として持つ。
4. 同一レーンの判断待ち提案は同時に1件までとする。
5. 一度記録された同一topicは状態にかかわらず再提案しない。
6. レーン作成は可逆な構造操作だが、ApproveとIntegrateは従来どおり人間だけが行う。
7. `pending`または`deferred`の提案が残るレーンは、`--force`を含めApproveできない。

## 判断状態

| action | 記録されるstatus | 意味 |
| --- | --- | --- |
| `create` | `created` | 子レーンを作成する |
| `continue` | `continued` | 親レーン内で検討を続ける |
| `defer` | `deferred` | 後で再判断する |
| `reject` | `rejected` | 分割しない |

`deferred`だけは後から別のactionへ変更できる。`created`、`continued`、`rejected`は確定状態とし、再判断を拒否する。

## 分割条件

AIは次をすべて説明できる場合だけ提案する。

- 親レーンとは異なる独立した判断または成果物がある
- 並行して検討できる
- 入力と出力の境界がある
- 他レーンや外部システムへの依存を列挙できる

単なる詳細項目、章の追加、小さな例外ケースは親レーンのセクションまたは注釈として扱う。

## 子レーンの構造

提案から作る子レーンは、目的、分割理由、対象範囲、利用者・関係者、品質目標・制約、依存関係・インターフェース、選択肢・判断、リスク・未決事項、受け入れ条件を持つ。親レーンと提案IDもメタデータに記録する。

この構造はArchitecture Inception Canvas、Impact Mapping、Domain Storytelling、ADRの考え方を軽量に取り込んだもので、すべての欄を最初から確定することは要求しない。未確定な欄は対話で埋める。
