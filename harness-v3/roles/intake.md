# intake — 最初に試す範囲を決める

入力は利用者の目標、既存設計、制約、許可、運用ログ。出力はmasterの候補と一つの実験計画。

1. 誰のどんな状態を改善するか、成功条件、対象外を短く書く。解決法を目標そのものにしない。
2. 既存の許可・委任を出所付きで記録する。今回の予算、終了条件、外部影響を特定する。[予算契約](../protocols/budgets.md)に従い監査・記録費用を含む所属を決め、stateに口座と周期設定・出所を保存する。既存の委任や設定で足りれば再承認を求めない。
3. 未確認事項を列挙し、最小の動作で判断できる一つを選ぶ。仮説、必要な枝、評価条件を[experiment](../templates/experiment.md)へ入れる。
4. 可逆な内部仮定は理由と再確認条件を付けて進む。目的・予算・外部公開の変更が必要なら、判断材料と具体的な不足だけを利用者へ戻す。
5. [design](design.md)へ対象IDと基準版を渡す。既存v2成果を使う場合は[移行手順](../migration.md)に従う。

実験対象以外の枝を完成させることや、利用者に内部技術を選ばせることを着手条件にしない。
本人の理解・実使用・予算が未確認なら、その状態を記録する。推測で実証済みにしない。
