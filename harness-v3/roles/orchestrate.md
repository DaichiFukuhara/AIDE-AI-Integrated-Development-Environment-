# orchestrate — 保存状態から続きへ進む

会話の記憶よりstate、操作、実験、監査の保存済み版を優先する。次を順に確認する。

1. 書込み中断があれば、最後の完全なstate/currentと台帳から表示を復元する。
2. 未処理変更を影響計算し、旧候補・監査結果をstaleにする。新しい同一性で再確認する。
3. 未確定取消、受信済み結果、終端通知、送信待ちをrecordへ渡す。確定済みIDを新操作へ再利用しない。
4. 作業開始時の観測時刻で期限を確認し、必要なperiodicを保存・送信する。既存要求と対応付ける。
5. 必要な監査を先に処理する。影響scopeの進行だけを保留し、原因解消の候補作成・検証は委任内で続ける。
6. checkedの計画はexperimentの追加実行前の予算確認へ渡す。保証不能ならpausedを維持する。評価済みの採用候補はrecordへ、構造不足はdesignへ渡す。
7. 次の未確認事項を選び、目標・予算内で新サイクルを始める。必要な枝から進め、幅を揃えない。

サイクルの完了は、終端、関連操作の確定、通知ack、必要な周期判定または差分なしskip、未解決事項・次の選択が保存されていること。
プロジェクト完了は、選択した必須条件と関連するUT/SIT/FIT、必要な実使用・人の評価、監査要件を満たすこと。
計画合格や一つの試行の成功を、全体完成と表示しない。

引継ぎにはcurrent_bundle、対象サイクル、操作ID、未送信要求、scopeごとの基準・差分・期限・保留理由、次の担当を短く示す。
