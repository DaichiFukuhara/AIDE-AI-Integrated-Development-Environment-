## 親からの振り分け

<!-- 親（handoff）が split-h1 の承認時に転記した。子は書き換えない。

- 責任: 閉包の受領・版の保持・開始可否・起票・**停止と再開**の順序を決める（外部との出入り）
- 詳細化の対象: 本文1の決定照合ゲートのうち**順序と外部との出入りの部分**。`s1.closure` の受領と開始可否、
  `s3.gap` / `s4.boundary` の起票、`s6.halt` の受領（**停止と再開の両方**）と旧閉包の凍結、
  受領確認の返送。
  **持ち越された重大1件**: `h2.findings` が閉包版しか識別せず、同じ閉包版で複数の
  成果物差分を照合したとき、どの `h1.criteria` パケットへの応答か判別できない。
  隔離結果を常に破棄して `h1` からやり直すか、相関を要求するかをここで決める
- 継承する制約: 根の不変条件1〜4と `boundary_requests` の例外、根の「親に残すもの」1〜15、
  ツール固有機能に依存しないこと（Codex / Claude の双方で回る）、予算（深さ3・子数5）。
  handoff の「親に残すもの」1〜11。とくに 3（人間の権威化まで確定させない）、
  4（境界契約だけ。implement の内部手順は作らない）、6（封筒も payload 書式も決めない）、
  8（模擬実装は gate が用意する。ただし照合材料に関しては完全性・版・順序の管理に限る）
- 割り当てられた受け入れ条件: 起票の対応 / 版の保持 / 停止の実効 / 再開の実効
- uses_seams: `h2.findings`（`detect` から: 分類結果、または「判定不能」）
- 提供する seam: `h1.criteria`（`detect` へ）。および親を経由して外へ出る `s3.gap` / `s4.boundary` の
  payload と、`s6.halt` への受領確認（`halt_ack` および再開の受領確認）
- 親から降りる入力: `s1.closure`、`s6.halt`（停止と再開）、および `s3` / `s4` の応答（受理・却下・再提案要求・失効）。
  **`uses_seams` には書かない。**親（handoff）が受けて権威化し、この節を更新して降ろす
