## 1. これは何を決めるものか

<!-- 深さ1: 課題の範囲と、それに対する解決法 -->

### 課題の範囲（親の振り分けより所与。ここでの決定対象ではない）

**設計を決める局面** —— あるノードについて人間と AI が内容を決め、人間が承認し、
子へ降ろすまでの区間。実装する局面（兄弟 `handoff`）と、決定が変わる局面
（兄弟 `change`）は含まない。

### 解決法（interview Q1 の回答。2026-08-29 人間が選択）

**検査を先に決め、書式をそれに従属させる。**

「通して読めるか / 所有者が一意か / 欠けが見えるか / cold start で再現するか」を、
ツリーと `harness/` だけを入力として、人間でも AI でも実行でき**合否が一意に決まる
検査手順**として先に定義する。ノードの書式は、その検査を通すために必要な分だけ決める。

この解決法は、次の2つを規則として含む。

- **検査できない書式規則は作らない。** 守られているか確かめられない規約は守られない
- **検査できない受け入れ条件は書かない。** 根が「満足できたら終了」を却下したのと同じ理由
  （`harness/criteria/precedents.md` 2026-08-25）

> 💬 **AI**: 案は AI が3つ出し（検査先行 / 書式先行 / 検査のみ）、人間が「検査を先に決め、
> 書式を従属させる」を選びました。選択そのものは人間のもので、上の本文は AI が書いた
> 案文です（`harness/roles/interview.md`「人間の答えはそのまま書く」への注記）。
> （2026-08-29）

> 🧭 **AI**: この解決法を採ると、深さ2の分割は「検査項目ごと」に切りたくなります。
> しかしそれは根の split-3 が取り下げられた切り方（受け入れ条件をそのまま写す）と
> **同型**であり、条件に現れない課題が落ちて seam が増えます。分割提案では、この罠を
> 明示的に比較対象へ入れます。（2026-08-29）

## 2. なぜ要るのか

祖先から継承（出所: 根の 2）: 現状人間の把握している機能・システムがなく、そのせいで
説明をすることや製品に対し責任を持つことができない。

この局面での具体形（出所: 根の split-4 の子定義と、受け入れ条件の割り当て）:

1. **残らない**: 決めたことが会話に閉じ、ファイルに残らない。次のセッション・別モデルで
   再開できない
2. **通して読めない**: 残っていても、量と構造の問題で通して読めず、人間が全体を説明できない
3. **持ち主が決まらない**: どの決定・どの境界が誰のものか決まらない
4. **欠けが見えない**: 決めるべきなのに決まっていないものが、ツリーを読んでも分からない

> 🧭 **AI**: 4 は根の受け入れ条件「整合」のうち**欠落の側**として `authoring` へ
> 割り当てられたものです。鮮度（古い決定が残っていないこと）は兄弟 `change` の担当で、
> ここでは扱いません。両者の論理積は、子が全部 `done` になった時点で根が再検査します
> （根の「親に残すもの」12）。（2026-08-29）

> ➕ **AI**: 1〜4 は仮説ではなく、**このツリー自身で観測できます**。根の `index.md` は
> 650 行あり、その大半が却下・取り下げ済みの分割提案（split-1 / split-2 / split-3）です。
> 現在有効な決定（`root@2026-08-29-decision-2` と split-4）を読み取るには、無効な提案を
> 読み飛ばす必要があります。受け入れ条件「把握」は、木の最初のノードで既に満たされて
> いません。（2026-08-29）

      祖先から委譲された宿題）を、ツリーを読むだけで**列挙できる**。検査はその列挙に

## 分割提案 split-1

status: pending    # pending / approved / rejected

前提: このノードの決定 `authoring@2026-08-29-decision-1`（固定質問1〜7）は
2026-08-29 に人間が承認済み（status: active）。

深さ1の決定「**検査を先に決め、書式をそれに従属させる**」を、深さ2の解決法へ詳細化する。
選び直しはしない。

### 子

- `decided`: **現行の決定を、誰のものか込みで読み取れる形にする。**
  何が有効な決定で、どれが無効になったもので、誰が書いたかを、ツリーを読むだけで
  一意に取り出せるようにする仕組み
- `undecided`: **決まっていないものを、ツリーから列挙できる形にする。**
  決めるべきだと分かっているのに決定が無い箇所を、印し、集め、列挙漏れが無いことを
  判定できるようにする仕組み

2つは**補集合**である。「決定がある場所」と「決定が無い場所」で切っており、
受け入れ条件を子へ写したものではない（下記「切り方の理由」）。

### seam

- id: `u1.orphaned`
  from: `decided` / to: `undecided`
  内容: **決定が無効になったのに後継が無い箇所**（穴が空いたこと）の通知。
  `s5.invalidation` で `change` から降りてきた失効を `decided` が反映した結果、
  後継の決定が無いまま空いた箇所を `undecided` の列挙対象へ渡す

seam は1本。数え落としが起きやすい経路を先に検査した結果を記す
（`harness/criteria/precedents.md` 2026-08-25「幸せな道だけを数えて過小計上する」）。

| 疑った経路 | 判定 |
| --- | --- |
| 未決が埋まって決定に変わる遷移（`undecided` → `decided`） | **seam ではなく共有状態。** 同じ `index.md` の同じ節を書き換える。親が書き込み権限と遷移を固定する（親に残すもの3） |
| 印の記法の衝突（両子が同じ `index.md` に印を付ける） | **seam ではなく共有状態。** 親が名前空間を固定する（親に残すもの2） |
| `decided` が「これは未決だ」と判定する競合 | 親の語彙固定（親に残すもの2・8）で起きない |
| 失効の反映（`change` → `authoring`） | 親の routing で `decided` へ降ろす（親に残すもの6）。子同士を通らない |
| 検査に落ちたときの是正 | 子を通らない。そのノードの担当が直す（親の Q6 決定） |
| 閉包の組み立て（`s1.closure`） | 親が両子の出力を合成する（親に残すもの7）。子同士の受け渡しではない |

### 親に残すもの（項目名ではなく、ここで決める）

1. **検査の共通形式。** 1つの検査は「入力（何を読むか）/ 手順（何を数え、何と突き合わせるか）
   / 合否（一意に決まる条件）」の3点で書く。**合否は「数える」か「引き当てる」で出す。**
   「読んで判断する」を合否条件にしない。2つの子が別々の検査形式を発明するのを防ぐ
2. **印の名前空間を1つにする。** `decided` が付ける印（**決定の状態**）と `undecided` が
   付ける印（**決定の不在**）は、同じ名前空間の中で衝突しない別語彙を使う。
   決定の状態は `status`（`active` / `superseded` / `rejected` / `withdrawn`）を使い、
   決定の不在にはこの語を使わない。どちらの語彙かで所有者が決まる
3. **未決が決定に変わる遷移は seam ではなく共有状態。** 同じ `index.md` の同じ節を
   書き換えるため。書き手はそのノードの担当（根の「親に残すもの」2）。
   遷移そのものの記録は `decided` の証跡規約に従い、`undecided` は印を消すだけ
4. **検査の実行タイミングと実行者。** 決定の承認の前と、分割の承認の前に回す。
   回すのは提案した AI と前検査の AI。合否は人間の承認の入力になるが、**拒否権は無い**
   （`harness/roles/precheck.md` と同じ扱い）
5. **落ちたときの扱い。** 直すのはそのノードの担当。`authoring` の子が負うのは
   「どのノードが、どの検査に、なぜ落ちているか」を示すところまで
   （親の固定質問6 の決定）
6. **seam の入出力の routing。** 根の「親に残すもの」9 に従い、親が権威化して降ろす。
   `authoring` の `## seam_inbox` が受け口になる

   | seam | 向き | 内容の種別 | 降ろす先 |
   | --- | --- | --- | --- |
   | `s3.gap` | handoff → authoring | 決まっていないことの要求 | `undecided` |
   | `s3.gap` | handoff → authoring | 実装時に実際に決めた事実の記録要求 | `decided` |
   | `s5.invalidation` | change → authoring | 失効の通知 | `decided` |
   | `s5.invalidation` | change → authoring | 書くべきだが無いものの要求 | `undecided` |
   | `s1.closure` | authoring → handoff | 閉包 | 両子の出力を**親が合成**する |
   | `s2.change-event` | authoring → change | 変更の単位と通知 | `decided` が出し、親が降ろす |

7. **`s1.closure` の payload。** 根の「親に残すもの」10 が「`payload` の書式は親では
   決めない」として `authoring` へ残した決定。閉包（自ノード＋祖先チェーン）の各ノードに
   ついて、次の3つが揃ったものとする。**3つ揃って初めて実装を始めてよい。**
   - (a) 現行の決定（`decided` の出力）
   - (b) 検査の合否（両子の検査結果）
   - (c) 未決の一覧（`undecided` の出力）
8. **共通語彙**（根の「親に残すもの」3 に足す。兄弟が別の言葉で同じものを呼ぶのを防ぐ）
   - *現行の決定*: そのノードで最後に承認され、失効していない決定
   - *未決*: 決めるべきだと分かっていて、まだ決定が無いもの
   - *検査*: 入力・手順・合否の3点を持つ手順。合否が読み手によって割れないもの
9. **親自身の決定**（子はこれを詳細化する。選び直さない）: 固定質問1の解決法、
   固定質問4の受け入れ条件7つ、固定質問6の線引き
10. **根から継承した制約すべて**: 不変条件1〜4と `boundary_requests` の例外、
    ツール非依存（スクリプトを書いてもよいが、無くても人手で同じ合否が出せること）、
    根の「親に残すもの」1〜12、予算（深さ3・子数5）、承認の2種

### 受け入れ条件の割り当て

| 親の受け入れ条件 | 担当 |
| --- | --- |
| 検査可能 | `decided` と `undecided` が、それぞれ自分の検査を親の共通形式（1）で書く。形式の統一は親 |
| 書式の従属 | 各子が自分の作った書式規則について。名前空間が衝突しないことは親（2） |
| 自己適用 | **親（`authoring`）。** 子が両方 `done` になった時点で、このツリー自身へ検査を通す |

| 所在 | `decided` |

### 切り方の理由（他の切り方との比較）

- **検査ごとに切る案（把握 / 所在 / 再現 / 整合）**: 根の split-3 と**同型**。受け入れ条件を
  子へ写しただけになり、条件に現れないもの（印の名前空間、未決が決定に変わる遷移）が
  落ちる。さらに4条件のうち3つが同じ書式要素（現行と無効の区別）を共有するため、
  共有状態を親へ上げないまま切ると seam が3〜4本に増える。
  **この罠は親の固定質問1に AI 注記として書いてあり、意図的に避けた**
- **検査と書式で切る案（inspection / notation）**: 親の決定が「書式は検査に従属する」で
  あるため、書式側の決定はすべて検査側から降ってくる。子が独立に決められず、
  依存の全量が seam を通る。分割基準（切ったあと子同士が親の前提だけで独立に決められる）を
  満たさない
- **同一性を独立の子にする案（identity / decided / undecided）**: 版参照の書式は根が既に
  決めており（`<node-id>@<日付>-<種別>-<連番>`）、`authoring` に残るのはハッシュの
  計算方法だけ。子1つ分の決定量が無く、seam を1本増やすだけになる。
  `decided` の下、深さ3へ置く
- **運用（いつ誰が検査を回すか）を子にする案**: ハーネスの演者を子にするのと同型で、
  split-1 / split-2 が却下されたのと同じ誤り。親の1決定（親に残すもの4・5）として書いた
- **分割しない案**: 深さ1は必ず分割する（`harness/README.md`）。また `decided` と
  `undecided` は判定の時点が違う（前者は決定が入ったとき、後者は決定が無いことに
  気づいたとき）ため、同じノードに置くと所有者が一意にならない
- 子は2つ、深さ2、seam は1本。予算（深さ3・子数5）内
