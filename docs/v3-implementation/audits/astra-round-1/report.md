**AIV3-001 — major / open：予算上限を保証できない場合の継続禁止が不足**

- **設計条件／基準：** SC4、C-SCOPE、AIDE-01。`docs/v3-design/root/subgoals/sg-learn/approaches/a-learn/systems/s-cycle/design.md:110`は、計測不能な費用を不明と記録し、上限を保証できない追加実行を禁止している。
- **実装箇所：** `harness-v3/roles/experiment.md:9–16`、`harness-v3/templates/trial.md:11`。費用の`unknown`は保存できる。一方、継続手順は「同一計画なら新trial」「中断後に残予算確認」「上限到達時に停止」で、上限到達を判断できない状態の扱いがない。
- **具体的反例：** 金額上限付きの実験で、最初の試行費用が計測不能となり、追加試行の費用上限も不明になる。担当は`budget_used: unknown`を保存し、中断せず同一計画の修正試行へ進める。上限到達は確認できないため、記載された停止条件は発火しない。しかし設計では、この時点の追加実行は禁止される。
- **影響：** 予算を明示的に増額していなくても、委任された上限を保証できない実行を継続し得る。「予算を暗黙に拡大しない」という一般規則だけでは、この状態での具体的な分岐を代替できない。
- **最小の解消条件：** 各追加実行前に、残予算または保守的な費用上限で実行可能性を確認する。保証不能なら追加実行を止め、証拠・不明額・再開条件を保存する手順を明記する。費用が不明でも安全な上限を保証できる場合まで、一律停止させる必要はない。手動のシナリオ確認で検証可能。
- **owner：** S-CYCLE実行規約担当。
