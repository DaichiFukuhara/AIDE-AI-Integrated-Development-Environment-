# 予算が不明な場合の手動シナリオ確認

対象: roles/experiment.mdの追加実行前の予算確認、experimentのbudget_check。主担当の手動照合であり自動実行テストではない。
合意した金額上限を10とする。いずれも目的・委任・対象版は変わらない場合。

| 状況 | 判定 | 保存と再開 |
| --- | --- | --- |
| 直前使用量unknown、累積上限も不明、次試行上限3 | 追加試行を開始せずpaused | 不明額・証拠・停止理由を保存。計測または根拠ある累積上限が必要 |
| 実測unknownだが累積上限6を契約条件から保証、次試行上限3 | 6+3≤10なので継続可 | 保守的上限の根拠と現在も前提が成立することを保存 |
| 累積実測8、次試行上限3 | 8+3>10なので開始しない | 上限1以下の小さい試行へ見直すか、明示的な予算変更が必要 |
| 累積実測4、次試行上限unknown | 追加試行を開始せずpaused | 次試行の上限が定まってから再判定 |
| 金額は範囲内だが時間の残りが不明 | 開始しない | すべての合意上限について保証が必要 |

中断していない修正試行にも毎回適用する。unknownを0として加算しない。pausedを終端へ自動変換せず、再開条件を保持する。
結論: AIV3-001の反例は停止経路へ入る。実測不明でも保守的上限で保証できるケースを一律には止めない。
